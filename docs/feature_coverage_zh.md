# 功能覆盖与后续演进计划

> [English](feature_coverage.md)

本文是 SQLConduit 1.0 当前能力的统一清单，分别回答三个问题：功能是否已经实现、验证范围有
多大、后续工作属于已排期还是仅在评估。快照日期为 **2026-09-29**；具体版本仍以对应的
CHANGELOG 为准，每个发布版本都应复核本文。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| **已实现 / 已验证** | 已通过文档化 API 提供，并有单测/契约测试和适用的实库集成测试 |
| **已实现 / 扩大验证中** | 当前可用，但仍在扩大跨版本、异常、压力或平台验证矩阵 |
| **进行中** | 正在执行测试、加固或实现，尚未提升到下一状态 |
| **已排期** | 已接受进入后续 1.x 迭代；进入 milestone 前不承诺具体版本日期 |
| **评估中** | 正在研究设计或厂商能力，不构成交付承诺 |
| **不在范围** | 项目明确不准备提供 |

`CompatibilityFallback` 是已经实现并受支持的执行模式，不等于假装完成 native 异步。只有
驱动真正以非阻塞方式启动操作时才报告 `Native`，其他 future 操作会明确报告 fallback，并
继续受到队列、超时和统计约束。

## 正在扩大验证的内容

下列功能已经实现，当前工作重点是增加测试和加固，而不是重新设计公共入口：

- 网络中断、取消失败、重连、池耗尽和关闭竞争；
- 长时间并发、反复 reload、游标遗弃和 prepared cache 淘汰；
- 四种驱动的大体积、多字节、二进制参数及批量中途失败；
- MySQL native async 在 Oracle MySQL 与兼容 MariaDB 客户端版本间的差异；
- ODBC Unicode、参数数组和取消在 FreeTDS/Microsoft ODBC Driver 上的差异；
- Oracle LOB、隐式结果、Array DML fallback 和 OCI 客户端版本组合；
- macOS/Windows 实库 smoke，补足现有编译和单测覆盖；
- Benchmark 历史、方差控制和跨版本性能回归阈值。

## 后续 1.x 迭代方向

以下按优先级排序；只有进入 release milestone 后才确定具体版本和日期。

| 工作项 | 状态 | 规划阶段 | 保持冻结入口的方式 |
| --- | --- | --- | --- |
| 故障注入与四驱动测试扩展 | **进行中** | 1.0.x 加固 | 只增加测试并在现有契约后修复 |
| 依赖/安装诊断与配置工具 | **已排期** | 下一个 1.x 次版本 | 工具和 CMake/配置元数据只做增量扩展 |
| 历史性能回归门禁 | **已排期** | 下一个 1.x 次版本 | 只改变 Benchmark/CI |
| 分配、连接池竞争、批量和游标优化 | **已排期** | 贯穿 1.x 逐步交付 | 保持现有方法和结果语义 |
| `StreamSource` 增量消费 | **已排期** | 后续 1.x | 复用当前类型和重载 |
| ODBC/Oracle native async | **已排期** | 后续 1.x，受厂商能力验证约束 | 复用 future API，真正 native 后才改变 `AsyncMode` |
| SQL Builder 方言扩展 | **已排期** | 后续 1.x | 新增扩展类型，可移植 Builder 继续有效 |
| 可选协程/Tracing 适配器 | **评估中** | 未分配版本 | 在 future/Observer event 上增加独立可选头 |

### A — 可靠性与采用体验

- 扩大故障注入与四库集成场景，增加升级/重连和事务结果不确定性测试；
- 改善依赖发现和错误提示，增加可维护的包管理器消费方式，但不捆绑厂商 SDK；
- 保存可复现的性能历史，并对超过约定阈值的稳定回归设置发布门禁；
- 围绕现有版本化 Schema 和错误模型增加配置检查/迁移工具；
- 补充运维排障文档和更可执行的厂商错误上下文。

### B — 吞吐与内存

- 减少参数转换、行物化、SQL 指纹和 mapping 分配；
- 扩展驱动原生批量快速路径，但保持 `executeBatch` 原子契约和事务 fallback；
- 厂商 API 允许时实现真正的增量 `StreamSource`，仍复用现有类型与重载；
- 优化游标预取和背压，不改变 `Cursor` 所有权和 fetch 语义；
- 增加缓存/连接池竞争和尾延迟基准，以测量结果驱动优化。

### C — Native 异步覆盖

- 对支持可靠异步模型的 ODBC Driver 实现 native ODBC async；
- 在能够保证取消和连接复用安全时实现 Oracle OCI native/nonblocking 状态机；
- 厂商能力允许时，把带参数 MySQL 及复杂路由/重试/缓存路径移出兼容 worker；
- 评估基于现有 future 的可选协程适配头，future 入口继续保留且不变。

### D — SQL 构造与观测

- 通过新增方言扩展对象支持分页、生成键、Upsert 和锁；可移植 Builder 不静默猜方言；
- 只有在参数顺序和标识符安全可机械验证时，才新增 JOIN/表达式组合；原始 SQL 始终保留；
- 在现有 Observer event 上增加可选 tracing/export adapter，例如 OpenTelemetry；现有指标名和
  稳定标签不改变；
- 增强 fallback 原因诊断，让生产环境能确认为什么没有进入 native/优化路径。

## 评估中，尚未承诺

- 自定义 executor 注入及 sender/receiver 集成；
- 具有 C ABI 的动态二进制驱动插件；
- 新增更多数据库驱动；
- 自动数据库 Schema 迁移规划。

项目不计划成为完整 ORM，不推断实体关系、不提供懒加载、不翻译任意 SQL 方言、不内置指标
HTTP server，也不承诺 exactly-once 写入。

## 如何保持冻结入口不变

最终规则以[公共 API 稳定性约定](api_stability.md)为准，后续迭代遵守以下限制：

- 1.x 内现有 `Client`、`Session`、`Cursor`、`Builder`、结果和状态签名继续有效；
- 新能力使用新增重载/类型或可选配置，默认值必须保持当前行为；
- Driver SPI 新增能力必须提供默认实现，1.x 内不把可选能力变成新的纯虚函数要求；
- 性能优化放在现有契约背后，native/fallback 仍通过 `AsyncMode` 和统计可见；
- 错误码数值、配置键、指标名/类型/标签不得复用或不兼容修改；
- 先弃用、后移除，不兼容删除等待 2.0；
- 无法保持语义的优化继续使用安全 fallback，或者新增显式 opt-in，不静默改变行为。

每个发布版本在能力状态发生变化时，必须同时更新本文、已知限制和发布检查表。
