# 测试策略与覆盖范围

> 基础版本：[English](test_strategy.md)

本文说明 SQLConduit 的各类测试能够证明什么、在哪些环境执行，以及哪些风险尚未完全自动化。
断言数量多不等于完整覆盖。每个 `1.x` RC 都应结合
[功能覆盖文档](feature_coverage_zh.md)和[已知限制](known_limitations.md)复核本矩阵。

## 发布门禁

| 风险 | 自动化证据 | 发布门禁 |
| --- | --- | --- |
| 公共 API 与配置契约 | 独立头文件编译、公共 API 断言、JSON/YAML Schema 和严格错误路径测试 | Linux、macOS、Windows 构建 |
| 核心行为 | 22 个非实库 CTest，覆盖映射、SQL Builder、连接池、会话、事务、重试、路由、异步、可观测性、插件、缓存和生命周期 | 所有 CI 构建平台 |
| 驱动真实行为 | MySQL、PostgreSQL、SQL Server/ODBC 实库套件，以及具备 OCI 环境时的 Oracle 套件 | MySQL/PostgreSQL、FreeTDS SQL Server 是托管 CI 门禁；Oracle 是明确的人工发布门禁 |
| 未定义行为与泄漏 | 全部非实库测试在 ASan、LeakSanitizer、UBSan 下执行 | Linux 托管 CI |
| 数据竞争与锁正确性 | 缓存、连接池和执行器竞争测试在 ThreadSanitizer 下执行 | Linux 托管 CI |
| 性能 | 12 个 Release 微基准输出 JSON 并归档 | Linux 执行；在同等硬件上比较，不使用托管 Runner 的绝对耗时阈值 |
| 源码覆盖率可见性 | GCC/gcov 生成核心及公共头文件的 XML、HTML 报告 | 报告必须成功生成；稳定采集基线后再设置数值门槛 |

## 缓存专项验证

结果缓存已经直接覆盖：关闭时短路、TTL 过期、命中/未命中计数、LRU 顺序、条目和近似
内存上限、超大条目拒绝、替换、返回值副本隔离、精确的数据源失效、热配置，以及并发
get/put/invalidate。集成测试还验证写后失效，并防止脱敏结果或影子流量越过缓存边界。

预编译语句缓存由四套实库驱动测试验证复用；能够观察淘汰行为的驱动还会验证容量限制。
原生句柄释放经过实库套件的关闭路径；sanitizer 目前覆盖驱动无关的所有权层。驱动内部占用
不计入结果缓存的近似字节统计。

## 性能与竞争

微基准覆盖连接借还、8 线程连接池竞争、参数绑定、SQL 构建、行映射、批处理、游标、关闭
日志，以及结果缓存的关闭/命中/未命中/替换路径。CI 保存 5 次测量中位数。

性能对比必须使用同一空闲机器、编译器、优化级别和电源策略；可重复的 10% 以上退化需要
调查。托管 Runner 的 CPU 分配和负载不稳定，因此只作为趋势信号，不设置固定纳秒门槛。

## 内存与资源生命周期

LeakSanitizer 对整个非实库套件启用，并用非零退出码报告泄漏。生命周期专项测试还验证连接
创建/关闭计数平衡、连接池重复销毁、执行器已接收任务全部排空，以及取消延迟任务后释放其
捕获对象。实库测试验证游标和会话会及时归还连接。

这能发现不可达分配、释放后使用、重复释放和常见资源生命周期回归，但目前尚未设置进程
峰值 RSS 或长时间堆增长预算。

## 明确存在的覆盖缺口

以下项目不能宣称已经全面验证：

- Oracle 实库测试需要 OCI 环境，尚未进入 GitHub 托管 CI。
- 托管 SQL Server 集成测试使用 FreeTDS；Microsoft ODBC Driver 实库执行不属于 1.0.0
  已验证矩阵，Windows CI 目前只提供 ODBC 路径的编译和单测验证。
- 自动版本矩阵尚未覆盖支持范围内的每个数据库小版本和客户端库版本。
- 微基准使用确定性的进程内驱动；端到端数据库延迟、吞吐、服务端计划缓存和网络背压需要
  受控的外部基准环境。
- 尚无定时多小时 soak、进程 RSS 增长门禁、网络分区代理或数据库故障切换 chaos 套件。
- 1.0.1 开发线已加入 ODBC/Oracle 原生异步状态机。Oracle OCI 查询/执行及 LOB 结果路径由手工
  实库套件覆盖；FreeTDS 明确验证 fallback。Microsoft ODBC Driver native 轮询仍需实库门禁，
  还需补充长耗时取消和并发 soak。

## 新增或修改功能时

每个已实现行为都应具有：确定性的单元或契约测试、失败路径测试；涉及厂商行为时增加实库
用例；改变所有权、并发、缓存或热路径时增加相应 sanitizer 或基准用例。只要本文对应项仍有
未处理缺口，发布说明就不能把该能力提升为“已全面验证”。
